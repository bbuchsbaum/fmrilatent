# fmrilatent Deep Audit — Executive Summary

**Date:** 2026-05-30
**Scope:** 62 R files (~16.6k LOC), 5 C++ files, 79 test files
**Verdict:** Architecturally sound, but five correctness defects silently corrupt real-data output today. Fix the P0 set before any release.

---

## 1. Methodology

Every R and C++ file received a per-file review across 8 cross-cutting dimensions: **correctness, architecture, consistency, tests, docs, quality, performance,** and a security/robustness pass folded into correctness. Findings were generated by category synthesizers and then **adversarially re-verified by an independent agent** — only confirmed findings are reported here. Suspected issues that failed verification (e.g., the DCT `norm="none"` reconstruction scare, `basis_pca` `whiten` forwarding, the retracted BOLDZip coverage gap) were downgraded or dropped and are recorded in the relevant section files.

Total confirmed findings: **254**. Full per-finding detail (file:line, repro, fix) lives in `audit/sections/*.md`.

## 4. Systemic Themes (root causes spanning multiple files)

1. **Round-trip-only testing hides shared-flaw bugs.** `decode(encode(x)) ≈ x` is the de-facto correctness gate, but forward and inverse share the same flawed permutation/normalization, so block ordering, spatial localization, and multi-block-root handling are wrong while tests stay green (drives findings #1, #2, #8). *Remedy:* assert intermediate invariants — partition of unity, per-block voxel counts on irregular masks, known-value spot checks.

2. **R-semantics silent corruption.** Vector recycling (Laplacian, AWPT scale weights), `t(apply())` dimension-drop, and `sapply` shape surprises produce wrong shapes/values without error (findings #2, #9). *Remedy:* prefer `vapply`/explicit `matrix()`; lint for `apply`/`sapply`/recycling hotspots.

3. **Validation deferred into internals.** Missing positivity/`NA`/finiteness/dimension guards defer failures into `RSpectra`/`Matrix`/C++ as cryptic errors (findings #4, plus the medium/low tail). *Remedy:* centralize in `.validate_*`; promote `.space_with_time_from_mask()` and `roi_subset_columns()` as single sources of truth.

4. **Factorization-convention drift.** `gram_factor`/metric conventions diverge across paths (ridged vs unridged, Cholesky vs QR vs eigen, weighted vs unweighted; analysis vs OLS coefficient space) — finding #10. *Remedy:* one documented convention with a shared helper.

5. **Wrong-distribution `noise_scale`.** Calibrated from the wrong distribution at three BOLDZip sites — unify the noise-scale policy (partially started in commit a8793e1).

6. **Incomplete classed-condition migration + sibling-constructor API drift.** Commit cccde9c converted only 12 files; BOLDZip, user-facing validation, optional-dep guards, and the C++ boundary still use bare `stop()`. In parallel, `spec_*` constructors disagree on `k`, `threshold`, `k_neighbors`, `scale`, and registry name mapping (findings #6 + the consistency cluster). *Remedy:* finish the sweep through `.encoder_cli_abort/warn`; adopt one spec-constructor/`encode_spec` signature convention.

7. **The base of the stack carries upward couplings.** `latent_handles.R` (2nd in Collate) hosts `%||%` plus unrelated mask/space utilities; handle materialization calls `lift()` (an upper-layer generic) and hard-codes `kind` as an enum in three places — external families cannot register handle-backed bases. *Remedy:* `register_handle_kind()` registry + a first-loaded `latent_utils.R` for zero-dependency primitives.

## 5. Architecture Verdict

**The core abstraction is sound. Keep it.**

`basis × loadings + offset` with lazy `BasisHandle`/`LoadingsHandle` materialization, an LRU registry, and spec-dispatch encoders is internally consistent and has **zero critical or high architecture defects**. The S4 `LatentNeuroVec` model, the encoder registry, and the spec → `encode_spec()` pipeline are the right shapes for this problem and should not be re-architected.

**Refactor (targeted, not structural):**
- Close the two leaking "openness" claims: add `register_handle_kind()` so the handle layer stops hard-coding `kind` and stops depending upward on `lift()`; make the `encode_spec` seam uniform (AWPT/transport currently abort and need separate entry points).
- Extract zero-dependency primitives (`%||%`, mask/space helpers) out of `latent_handles.R` into a first-loaded `latent_utils.R` to reduce load-order fragility (already flagged in CLAUDE.md).
- Make `.space_with_time_from_mask()` and `roi_subset_columns()` the single sources of truth for geometry and ROI indexing.

**Leave alone:** the data model, registry/cache design, S4 dispatch pattern, and the BOLDZip codec decomposition (correct, just under-classed in its errors).

## 6. Phased Remediation Roadmap

### P0 — Correctness (block release)
Fix the five criticals (#1–#5) and the wrong-output highs (#8 `concat` offset, #9 `t(apply)`, #10 coefficient-space mismatch, ROI-mask bypass). **Each fix ships with an intermediate-invariant test, not a round-trip test** — this directly retires systemic theme #1. Also correct the wrong-distribution `noise_scale` at the three BOLDZip sites.

### P1 — Consistency & Architecture
- Finish the classed-condition migration (#6); add the missing BOLDZip `test-*_error_classes.R` and a C++→R error-class translation layer.
- Fix cache-after-compute in the three handle constructors (#7) — restores the lazy-handle performance contract.
- Adopt one spec-constructor / `encode_spec` signature convention; resolve registry name mismatches (`st`, `space_hrbf`).
- Add `register_handle_kind()`; extract `latent_utils.R`.

### P2 — Tests, Docs, Quality, Performance
- Add path-isolated tests for the transport solver core (`encode_transport_solve.R`), shared validators (`encoder_validators.R`), and utilities (`encoder_utilities.R`).
- CRAN doc pass: add `\value` to the 10 exported pages, replace gratuitous `\dontrun{}` with `\donttest{}` or live examples, reconcile drifted contracts (`data`, `family`, `whiten`, `@include`).
- Quality: add `setValidity` to `HierarchicalBasisTemplate`, warn on silently-ignored args (`reduction` in `spec_space_parcel`, `k_time`), remove dead/duplicated code.
- Performance: introduce `.with_loadings_cache()`, a sparse-aware `.all_finite()`, dimension-only basis comparison in S4 validity, and time-subset-aware reconstruction to retire the densification cluster; switch singular-Laplacian solves from `which="SM"` to shift-invert.
